# Windows 本地节点验证程序

两个项目提供各自的 Windows x64 程序，适用于 Windows 11，无需安装 Python 或启动 v2rayN：

| 项目 | 下载 / 启动文件 | 电脑验证流程 |
| --- | --- | --- |
| [CF-vps Releases](https://github.com/zhangx16/CF-vps/releases) | `CF-VPS-Desktop-*.zip` → `CF-VPS-Desktop.exe` | 服务器已经完成探测；直接替换命中 IP 和端口到模板，进行真实节点请求与复测，**不再进行 TCP 初筛** |
| [NCV Releases](https://github.com/zhangx16/new-cf-vps/releases) | `NCV-Desktop-*.zip` → `NCV-Desktop.exe` | 保留 TCP 初筛，再替换 IP 和端口进行真实节点请求与复测 |

## 使用

1. 完整解压对应压缩包，双击 EXE。浏览器打开本机管理界面，不需要管理员权限。
2. 关闭电脑上的 TUN/VPN，或者自行配置候选 IP 直连。程序使用自己的 SOCKS，不读取系统 HTTP 代理；**不能自动绕过 TUN 系统路由**。
3. 在“网站任务”填写对应网站地址、账号密码。程序固定对应自己的项目，读取任务并拉取候选。CF-vps 拉取该任务的全部命中记录（疑似、Trace、双域名等），保留每个 IP 对应的端口。也可以粘贴/导入每行一条的 IP、IP:端口、CIDR 或 CIDR:端口 TXT，缺省端口默认 443。
4. 粘贴自己的 VLESS 模板，每行一个、最多 10 个，可填写地区标签。只替换连接 IP 和端口；UUID、SNI、Host、路径、TLS 参数保持。地区自行填写，不自动推断。
5. 默认真实请求并发 10、超时 6 秒，首次失败即跳过，成功候选默认共测 3 次。CF-vps 版没有额外 TCP 阶段；NCV 版默认 TCP 并发 200。
6. 按请求延迟查看结果，点击 IP:端口复制。导出全部复测通过的 VLESS、IP:端口或任务名 CSV。候选为 8443 时，导出也使用 8443。
7. 回填只发送去重的 IP 和端口，不发送模板。网站核对任务和精确端点：CF-vps 匹配命中记录，NCV 匹配 TCP 结果。CF-vps 的“电脑本地验证结果”支持查看、筛选、导出、移除标记，不改原探测证据、地区或收藏。
8. 暂停会取消当前请求并保存进度；“继续上次任务”跳过已完成的节点组合。**关闭网页不停止测试**，请使用“保存并退出程序”。每个程序当前各保留一个任务，新建前先导出需要保留的结果。

CF-vps 服务端需要升级到包含回填 API 的版本：`sudo cf-vps upgrade`。

## 更新、进度与数据

先在旧版页面点击“保存并退出程序”，再完整解压新版启动，确认版本是 `0.2.0-beta.2`。不要只关闭旧网页。

- CF-vps 版：`%APPDATA%\CF-VPS-Desktop\`，界面默认 `127.0.0.1:49784`。
- NCV 版：`%APPDATA%\NCV-Desktop\`，界面默认 `127.0.0.1:49783`。
- 同一程序再次双击会打开已有实例；两种程序可以独立运行。浏览器未自动打开时，打开对应数据目录里的 `打开界面.url`，该文件含本机访问令牌，不要分享。
- 旧通用版的 CF-vps 任务如仍保存在 NCV 目录，新 CF-vps 版首次启动时会识别并复制其进度，不删除原文件，不覆盖任何已有 CF-vps 任务。后续两边独立保存。旧 NCV 任务继续留在原目录。
- 状态文件包含**节点凭据原文**，仅保存在当前用户电脑，不要分享整个数据目录或 state.json。网站密码仅用于当前操作，不写入状态文件。
- 每 5 秒保存检查点，暂停时再次保存，保留上一个检查点作为恢复备份；异常退出后可能重测最近的小批次。
- Xray 临时配置正常停止后删除，下次启动清理残留；只结束程序自己的 Xray 子进程，Windows 使用 Job Object 清理。没有直连回退配置。

## Xray 启动错误

`exit status 0xffffffff` 是核心启动失败的退出码，本身不能确定原因。新版在测试前检查配置，使用 18000–27999 内空闲回环端口，绑定冲突时重新分配，确认全部本地入站就绪后再验证节点。核心意外退出会报错并保留进度。

具体核心输出会脱敏后显示在页面，同时保存到**该程序数据目录**的 `last-core-error.txt`。如仍失败，提供完整提示或此文件内容，不要提供 state.json。此前用户电脑上的具体失败尚未复现。

## 支持范围

- VLESS + TLS/Reality；WS、TCP、gRPC、HTTPUpgrade。暂不支持其他协议、XHTTP、自定义加密或关闭证书校验；不支持的模板参数明确报错。
- 每任务最多 20 万个不同 IPv4:端口、单 CIDR 不超过 /15；节点/IP 组合最多 50 万。真实请求并发 1–50，最多每批配置 200 个组合。NCV 的 TCP 并发范围为 1–1000，CF-vps 不使用此设置。
- 通过表示当前网络下完成所选 HTTPS 请求并通过指定复测次数，不表示带宽、解锁能力或长期稳定性。延迟包括握手与目标响应。
- 程序未代码签名。提供 SHA256；Windows 核心与程序在 Wine 兼容环境验证过，尚未完成 Windows 11 实机验证，仍为 Beta。

## 从源码构建

Go 1.23+、Python 3.8+，在对应仓库的 desktop/ 运行：

```sh
go test ./...
python3 package.py
```

脚本生成该仓库对应的 EXE，下载并校验固定版本官方 Xray Windows 核心，打包到 dist/。可设置 `GO=/path/to/go`，没有外部 Go 模块依赖。两个仓库共用测试引擎；profile.go 固定项目流程，package.py 固定对应程序文件名。

真实核心测试：`NCV_TEST_XRAY=/path/to/xray go test -race ./...`。包括真实 WSS/VLESS + HTTPS、错误 UUID 无直连回退、端口绑定诊断、暂停恢复、CF-vps 无 TCP 阶段和 NCV 保留 TCP 阶段。
