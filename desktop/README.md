# NCV Desktop（Windows 便携版）

下载：[NCV Releases](https://github.com/zhangx16/new-cf-vps/releases) 或 [CF-vps Releases](https://github.com/zhangx16/CF-vps/releases)。两个仓库发布相同的通用 Windows 程序。选择 `NCV-Desktop-*-windows-amd64.zip`，适用于 Windows 11 x64。

## 使用

1. **完整解压**压缩包，双击 `NCV-Desktop.exe`。无需安装 Python，无需启动 v2rayN，也无需管理员权限。程序在默认浏览器中打开本机管理界面（`127.0.0.1`）。
2. 先关闭电脑上的 TUN/VPN/全局路由代理，或者自行配置候选 IP 直连。程序显式使用自己的 SOCKS 连接，不读取系统 HTTP 代理；**不能自动绕过 TUN 的系统路由**。
3. 在“网站任务”选择项目类型（NCV 或 CF VPS），填写对应网站地址与登录信息，读取任务并拉取候选；也可粘贴/导入每行一条的 `IP`、`IP:端口`、`CIDR` 或 `CIDR:端口` TXT。默认端口仅用于没有写端口的候选。
4. 粘贴自己的 VLESS 模板（每行一个，最多 10 个），可填写地区标签。地区由你填写，不自动推断 IP 地区；多地区模板可同时验证，结果按模板区分。
5. 默认 TCP 并发 200、代理请求并发 10、超时 6 秒。先进行 TCP 检查，再用合格 IP 和端口替换模板的连接地址，保持 UUID、SNI、Host、路径、TLS 参数。首次代理请求失败即跳过；成功后继续测试，默认总计 3 次。
6. 查看结果，点击 `IP:端口` 复制。默认导出全部复测通过的 VLESS / IP:端口 / CSV，按真实请求延迟排序。文件名使用任务名。
7. “回填通过的 IP:端口”只发送去重后的地址与端口，不发送节点模板。网站会核对它们属于对应任务：NCV 匹配 TCP 通过记录，CF VPS 匹配保留的命中记录。不会把本地验证覆盖为原服务器探测证据，也不会自动收藏。CF VPS 服务端需升级到包含本地回填 API 的新版本。
8. “暂停”会取消当前请求并保存进度。“继续上次任务”跳过已完成的 TCP 与模板/IP 组合。重启程序也可续测。“保存并退出程序”会停止本机后台；**只关闭浏览器不会停止测试**。

## 从旧版更新 / Xray 启动失败

先在旧版页面点击“保存并退出程序”，再完整解压新版到新目录并启动，确认页脚版本是 `0.2.0-beta.1`。同一电脑会复用正在运行的实例，只关网页不会切换版本。任务文件沿用 `%APPDATA%\NCV-Desktop\`，无需删除，重新勾选 TUN 确认后点“继续上次任务”。

`exit status 0xffffffff` 是核心启动失败的退出码，本身不能确定具体原因。Beta 2 在 TCP 初筛之前检查配置；为每批分配 18000–27999 范围内空闲的本机回环端口，避开默认 Windows 动态客户端端口范围；发生绑定冲突时最多重新分配三次。它检查全部本地入站已就绪，并监控核心意外退出，避免将核心异常误记为整批节点失败。

新版显示实际核心输出（节点参数做脱敏），最近一次错误同时保存在 `%APPDATA%\NCV-Desktop\last-core-error.txt`。如仍失败，请提供页面中完整错误提示或该文件内容；不要发送 `state.json`，其中有节点凭据。程序不会为解决端口冲突而关闭其他软件或修改 Windows 的系统端口配置。

## 范围与数据

- 两个网站共用同一个本地工作空间，当前只有一个本地任务；创建新任务会替换旧任务。先导出需要保留的结果。
- 最多 20 万个不同 IPv4:端口；单 CIDR 不超过 /15；模板/IP 组合最多 50 万。TCP 并发范围 1–1000，代理并发 1–50。几万个 IP 建议先使用默认值，根据网络丢包与电脑资源逐步调整。瓶颈通常是网络和超时，而非显卡。
- 当前支持 VLESS + TLS/Reality，传输 WS、TCP、gRPC、HTTPUpgrade。暂不支持其他协议、XHTTP、自定义加密、关闭证书校验；不支持的参数会明确报错。
- 成功表示该候选在当前网络下能通过模板完成所选 HTTPS 请求，并通过所设次数的验证，不代表带宽、流媒体解锁或长期稳定性。请求延迟包含握手和目标响应，与 v2rayN 的不同测试指标可能不同。
- 每批最多为 200 个候选/模板组合建立本地入站；真实请求受代理并发限制。一个批次使用一个自有 Xray 子进程，暂停/退出时停止；Windows 使用 Job Object 清理子进程。配置无直连回退。
- 状态保存在 `%APPDATA%\NCV-Desktop\`（当前用户目录），包含**节点凭据原文**。不要分享该目录。主状态和上一个检查点轮换，每 5 秒保存，暂停时再次保存；异常断电最多损失最近一个检查点之后的进度。
- 网站密码仅随当前操作在内存中使用，不写入状态文件；程序不会主动上传模板。运行时 Xray 临时配置只写本机，正常停止会删除，下次启动清理残留配置。
- 同一电脑默认只运行一个实例；再次双击会打开现有界面。浏览器没有自动打开时，打开 `%APPDATA%\NCV-Desktop\打开界面.url`。该快捷方式包含本机访问令牌，不要分享。
- 未进行代码签名，Windows 可能显示未知发布者。发布包提供 SHA256。当前为预发布：Linux 下完成核心集成和界面测试，Windows 文件由交叉编译产生，尚未进行 Windows 11 实机验证。

## 从源码构建

Go 1.23+、Python 3.8+。在 `desktop/` 运行：

```sh
go test ./...
python3 package.py
```

脚本交叉编译 Windows amd64 程序，下载固定版本的 Xray 官方 Windows 核心，校验 SHA256，再打包至 `dist/`。也可设置 `GO=/path/to/go`。没有其他 Go 模块依赖。

真实核心离线集成（需要 Linux Xray）：

```sh
NCV_TEST_XRAY=/path/to/xray go test -race ./...
```

该测试创建本机 WSS/VLESS 服务与 HTTPS 目标，验证三次真实请求、错误 UUID 不会回退直连、系统代理环境变量不影响自有 SOCKS；测试证书仅供本地 fixture 使用，生产配置保留证书验证。
